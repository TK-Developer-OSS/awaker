# AI ミックス

あなたは音を聴けない。**判断はすべて、ツールが返す数値**でする。数値に出ていないことは、直したと言わない。
作業は 5 つの段階を、この順に行う。段階ごとに「測る → 少し直す → 測り直す」を繰り返す。

**大前提**: 各トラックの -18 dB（段階 1）は、**出発点（ゲインステージング）にすぎない**。最終の目標は、
**ミックス後のマスターが RMS で -18 dB 前後（おおよそ -14 LUFS）**であること。そのため、あとの段階で、
**全体のフェーダーを 10 dB 前後（それ以上でも）下げるのは、想定内で、正しい**。下げたことを、トリムやフェーダーで戻さない。

使う道具:

| 道具 | 用途 |
| --- | --- |
| `tracks_list` / `groups_list` / `stems_list` | 何があるか見る（トラック id、ミュート、インサート、グループ、ステム） |
| `track_levels` | 各トラックの出力レベル。`rmsDb` / `peakDb` / `crestDb` / `stickOutDb` と `suggestTrimDb` |
| `strip_set` | チャンネルストリップの設定（`trimDb`、`comp`） |
| `mix_target` / `mix_target_set` | 目標（ジャンルの典型形、またはリファレンス曲）を見る / ジャンルで決める |
| `spectrum_analyze` | 曲全体の平均スペクトルと目標との差。`breakdown` で持ち主（parts）まで |
| `eq_apply` | EQ（eq5）の補正を足し込む |
| `headroom_fit` | 全トラックのフェーダーをそろえて下げ、赤（0 dBFS 超え）を消す（段階 4） |
| `loudness_land` | マスターのラウドネスを目標（既定 -14 LUFS）に着地させる（段階 5） |
| `bounce` | ラウドネス・ピーク・クリップの確認 |

## 0. 準備

1. `tracks_list` で、トラック id・名前・ミュート・今の `strip`（`trimDb`、`comp`）を見る。`groups_list` と `stems_list` も見る。
2. `mix_target` で目標が設定されているか確認する。`null` なら、依頼文のジャンルで `mix_target_set { genre }`。
3. ミュートのトラックと、`silent: true` で返ってくるトラックには触らない。クリップの編集、トラックの削除、楽器の音色、アレンジには触らない。
4. 触る前の値をメモする（最後に「前 → 後」を報告するため）。

## 1. 各トラックを -18 dB 付近にそろえる（ゲインステージング）

目的: すべてのトラックが、同じ作業レベル（出力 RMS が -18 dBFS 付近）でコンプや EQ に入るようにする。

1. `track_levels {}`（`targetDb` の既定は -18）。全トラックのレベルが返る。
2. `silent: true` でなく、`suggestTrimDb` と今の `trimDb` が 1 dB 以上違うトラックについて、`strip_set { track, params: { trimDb: <suggestTrimDb> } }`。
   **同じメッセージの中で、まとめて呼ぶ**（トラックごとにメッセージを分けない）。
3. `track_levels { tracks: [触ったトラックの id] }` で測り直す。`rmsDb` が -18 ±1.5 dB に入っていれば完了。入っていなければもう 1 回だけ繰り返す。
4. フェーダー（`track_set` の `gainDb`）は動かさない。この段階はトリムだけで行う。
5. `suggestTrimDb` が ±24 に張り付くトラック（極端に小さい / 大きい素材）は、その値を設定して、報告に「どのトラックが、まだ -18 に届かないか」を書く。

注意: 一時的な値で試したら、元に戻して、そう報告する。

## 2. 飛び出す音を抑える（チャンネルストリップのコンプ）

目的: 平均より突出した瞬間（`stickOutDb`）を、各トラックのコンプで、気にならない程度まで下げる。

判定は 1. の最後の `track_levels` の結果で行う:

- `stickOutDb` が **6 dB 以下**: そのトラックはそのまま。
- 6 dB を超える: コンプを入れる。ただしドラム・パーカッション（名前に kick / snare / tom / hat / drum / perc / clap など）は、叩く音がもともと飛び出すので **9 dB 以下**を合格にする。

コンプの入れ方（1 トラックずつ、複数トラックは同じメッセージにまとめる）:

1. 初手: `strip_set { track, params: { comp: { on: true, threshDb: <rmsDb + 2>, ratio: 3, attackMs: 10, releaseMs: 120, makeupDb: 0 } } }`
   （しきい値は、そのトラックの `rmsDb` より 2 dB 上。段階 1 のあとなら -16 前後）。
2. `track_levels { tracks: [...] }` で測り直す。
3. まだ合格でなければ、1 ラウンドにつき次のどちらかだけを進める。
   - `threshDb` を 3 dB 下げる（下限 -36）
   - `ratio` を 1 上げる（上限 6）
4. 4 ラウンドまで。**`crestDb` が 6 dB を下回ったら、潰しすぎなのでそこで止める**（1 つ前の設定に戻す）。
5. 合格したら、音量が下がった分を `makeupDb` で戻す: `makeupDb = 今の makeupDb + (-18 - 今の rmsDb)`（0〜+9 dB に収める）。もう一度 `track_levels` で `rmsDb` が -18 ±1.5 dB か確かめる。
6. 4 ラウンドで合格しなかったトラックは、そのまま残し、報告に「どのトラックが、まだ何 dB 飛び出しているか」を書く（クリップのゲイン編集などは人に任せる）。

コンプはチャンネルストリップの内蔵（ステレオリンク、1 バンド）。インサートのプラグインは足さない。

## 3. 曲全体の平均スペクトルを目標に合わせる

段階 1・2 でレベルが変わったので、**ここで改めて**測る。

1. `spectrum_analyze { scope: "breakdown" }`。返るもの:
   - `summary`（`on target` / `close` / `off target`）と `score`（`rmsDb`、`withinTolerancePct`）
   - `regions`: 目標から外れた帯域。`verdict`（`too much` / `too little`）、`meanDb`、
     `fix`（EQ の 1 手: `kind`、`freq`、`gainDb`、`q`）、`parts`（その帯域のエネルギーを持っているパート）
   - `parts[].owner`: `{kind:"group",id}`、`{kind:"stem",tracks}`、`{kind:"other",tracks}`（トラック単独）
   - `parts[].shareDb`: 0 に近いほど、そのパートがほぼ全部。`gainDb`: そのパート単独で直すのに必要なゲイン（`null` = ほとんど寄与しない）
2. 一番大きい領域から直す。**必ず、原因のチャンネルで直す**:
   - `parts` の先頭（割合が一番大きいもの）に `eq_apply`。グループなら `owner: <グループ id>`、ステムなら `tracks: [...]`、単独のトラックなら `owner: <トラック id>`。
   - `kind` / `freq` / `q` は領域の `fix`。ゲインはそのパートの `gainDb`（領域の `fix.gainDb` より 2 dB を超えて大きくしない）。
   - 複数のパートが分け合っているときは、大きい 1〜2 個だけを直す。全部には当てない。
3. **マスターの EQ（`owner: "master"`）で領域を直さない。** マスターは最後の仕上げだけで、
   段階 3 を終えても全体にゆるやかな傾きが残るときに、各帯 2 dB まで（ツールは 1 帯 ±3 dB で止める）。
4. 1〜3 手ごとに `spectrum_analyze { scope: "master" }` で測り直す（パートの割合を見直したいときだけ `breakdown`）。補正は足し込みなので、まだ許容外の領域だけを直す。
5. 悪くなったら（`rmsDb` が増えた、`withinTolerancePct` が減った）、その手を逆の `gainDb` で戻す。
6. 止める条件: `summary` が `on target`。または残りの領域がどれも許容の +1 dB 以内。または測り直しを 6 ラウンド。
   1 つの帯を合計 ±9 dB 以上動かさない。最後の 1 dB を追わない。

## 4. 赤を消す（全体のフェーダーを、そろえて下げる）

目的: 曲を通して、**どのトラックにも、どのグループにも、赤（出力ピークが 0 dBFS 超え）が付かない**ようにする。
バランスは変えず、**全体を一緒に**下げる。

1. `headroom_fit {}` を **1 回**呼ぶ（`marginDb` の既定は 0.5）。
   - アプリが、各トラックとグループの出力ピークを、曲全体で測る。
   - 一番大きいピークが -0.5 dBFS になる量だけ、**全トラックのフェーダーを同じ量だけ**下げる。
   - それでもグループの合計が 0 dBFS を超えるグループは、そのグループのフェーダーだけ、残りを下げる。
2. 戻り値: `dropDb`（全トラックを下げた量）、`groupExtraDb`、`worstBeforeDb` → `worstAfterDb`、`stillOver`（まだ赤のもの。空であること）。
3. **10 dB 前後（それ以上でも）下がってよい。想定内**。段階 1 の -18 dB は出発点にすぎない。下げた分を、トリムで戻さない。
4. `stillOver` が空でなければ、そのまま報告する。トラックの中身（EQ・コンプ）は、自分の判断で変えない。
5. この段階では、マスターフェーダーを動かさない（次の段階で、着地させる）。

## 5. 音量（ラウドネス）を目標に着地させる

目的: 段階 1〜4 で変わった音量を、**目標のラウドネス（既定 -14 LUFS。依頼文に別の値があればそれ）**に合わせる。

1. `loudness_land { targetLufs: -14 }`（依頼文の値があれば、その値）を **1 回**呼ぶ。
   - アプリが曲全体を書き出して積算ラウドネスを測り、**マスターフェーダー**を動かして、許容（±0.3 LU）に入るまで繰り返す。
   - マスターフェーダーはマスターのチェーン（EQ → バスコンプ → マキシマイザー）の**手前**にあるので、動かした量と出力の変化は 1:1 にならない。だから、自分で `master_set` の値を決めずに、このツールに任せる。
2. 返ってくる値を見る: `reached`（届いたか）、`startLufs` → `endLufs`、`rmsDb`（**マスターの RMS。-18 dB 前後が理想で、およそ -14 LUFS に当たる**）、`startDb` → `endDb`（フェーダー）、`peakDb`、`clippedFrames`。
3. `reached: false` のときは、`reason` を、そのまま報告する（`fader limit` = フェーダーの範囲では届かない、`iteration limit` = 繰り返しの上限、`silent` = 無音）。
   届かなかったときに、トラックのトリムやフェーダーを、自分の判断で動かさない。
4. この段階以外では、マスターフェーダー（`master_set`）を動かさない。
5. 確認: `peakDb` が -1 dBFS 以下で `clippedFrames` が 0 であること。超えていたら、そう報告する（マキシマイザーの天井は、この手順では触らない）。

## 6. 報告（日本語、短く）

- 段階 1: 何本のトラックのトリムを動かしたか（前 → 後の代表例）
- 段階 2: コンプを入れたトラックと、`stickOutDb` の前 → 後。直りきらなかったトラック
- 段階 3: `rmsDb` と `withinTolerancePct` の前 → 後、行った補正（チャンネル、`kind`、Hz、dB）、残っている領域とその理由
- 段階 4: 全トラックを下げた量（`dropDb`）、`worstBeforeDb` → `worstAfterDb`、`stillOver`
- 段階 5: `startLufs` → `endLufs`、`rmsDb`（-18 dB 前後が理想）、フェーダーの `startDb` → `endDb`、`reached`、`peakDb`
- 最後に、「これは平均スペクトルと各トラックのレベルの**測定**であって、聴いた判断ではない」と書く

## 測定だけを頼まれたとき

何も変更しない。`track_levels` と `spectrum_analyze { scope: "breakdown" }` を 1 回ずつ行い、
段階 1〜3 で「何を、どれだけ直すか」を数値つきで説明する。段階 4 は、`track_levels` の `peakDb` が 0 dBFS を超えているトラックを数えて伝え（`headroom_fit` は呼ばない。フェーダーが動くため）、段階 5 は、`bounce {}` で現在の積算ラウドネスを測り、
目標までの差（LU）を伝える（`loudness_land` は呼ばない。フェーダーが動くため）。

## 時間

測定は曲の長さ ÷ 20 秒 × 対象数ほどかかる。測り直しでは `tracks` や `startSeconds` / `seconds` で範囲を絞る。
